# Phase 4 implementation plan

Prepared October 19, 2026, before Phase 4 pilot extraction. This develops the Phase 4 requirements in the redesign plan; methods remain subject to the Phase 7 lock.

1. Define strict public bundle schema 2 and a separate versioned context policy. Keep Phase 3 configuration, sources, binary artifacts and reviews unchanged.
2. Stage only a debug-free analysis binary under a neutral filename and an entry address for Ghidra 12.1.4. Use a new exporter rather than the historical single-function schema. The private coordinator may use reviewed localization, but no source name, label, capacity, function list or instruction range may guide traversal.
3. Starting at the recovered function containing the entry, traverse direct call and inter-function jump destinations by address. Include all reachable application/support functions and compiler clones. Preserve discontiguous bodies and inlined behavior in containing functions. Exclude external bodies and PLT thunks by binary linkage information, not developer names. Do not traverse runtime startup backwards from the entry. Record indirect/unrecovered transfers explicitly.
4. Export instructions with bytes and addresses, per-function decompilation status, direct edges, direct referenced data windows with raw bytes and uncertain interpretations, and completeness/omission facts. Keep actual retained names and Ghidra's own recovered names in each independently analyzed artifact. Never join names from a reference or its symbol partner.
5. Apply deterministic ordering and shared limits on functions, instructions, direct referenced data and canonical UTF-8 bundle bytes. Count UTF-8 bytes as a conservative token upper bound; actual chat-template/model budgeting remains Phase 6 work. Exceeding limits produces `context_unavailable`, never an available cropped bundle. Unresolved code, missing essential data or decompilation failure produces `extraction_unavailable` under this initial conservative policy. Every declared observation gets a record and a private disposition.
6. Validate strict schemas, instruction/range/data/edge membership, evidence addresses across functions, imported metadata, source-label leakage and extraction identities. After extraction, privately compare reviewed evidence addresses with the recovered scope; do not repair individual bundles using oracle contents. Audit actual symbol loss and identical/structure-equivalent groups with conflicting source labels.
7. Exercise independent fixtures for caller allocation/callee writes, tail calls, inlining, discontiguous bodies, unresolved transfers, data references and failure/budget handling. Run all 32 pilot observations twice in fresh Ghidra projects, check canonical equivalence, and run the repository regressions. Record the implementation, coverage, limits and any failed gate in a Phase 4 report.

No baseline or LLM predictions, final assignments, method lock or campaign freeze are part of this phase. Both methods must consume the same available bundle scope in later phases; inferred decompiler declarations do not establish object capacities.
