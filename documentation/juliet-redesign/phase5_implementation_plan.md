# Phase 5 implementation plan

The initial plan below describes v1. The October 20 [v2 amendment and evaluation](phase5_stack_revision.md) explicitly permits inferred stack-array extents and a narrow instruction-P-code store fallback before method lock.

October 19, 2026. Implement a bounded Ghidra high-P-code baseline before final selection; no LLM or final predictions are part of this work.

1. Review the predecessor `pipeline/static_baseline.py` and its regressions. Reuse public-schema validation, deterministic output/evidence conventions, failure separation and write-time feasibility principles. Do not port the single-function x86 simulator, saved-frame-overlap endpoint, historical IDs, implicit root configuration or source-label assumptions.
2. Preserve Phase 3 artifacts and Phase 4 public bundles. Reconstruct an isolated Ghidra memory image solely from the bundle's instruction/data bytes. Reuse the pinned Ghidra/version checks and public bundle/evidence validators. Export high P-code, recovered parameter slots and basic-block relationships only for declared functions, with fixed external library signatures. No decompiler object sizes or oracle joins establish bounds.
3. Implement a small constant/pointer rule engine over that IR: fresh allocation identities, constant extents, pointer offsets, direct calls, concrete branch feasibility and fixed allocation/copy/string/output contracts. Support only bounded acyclic execution; loops, unresolved branches, aliases, recursion and unsupported calls abstain. A feasible overflow witnessed before later unsupported behavior remains evidence; speculative paths never establish findings. A safe result requires all admissible modeled paths and selected writes to be accounted for.
4. Test independent safe/overflow copies, missing capacities, separate caller/callee allocation/write flow, multiple allocations, unknown calls, infeasible branches, direct stores and compiler-inlined copies. Verify bit widths and arithmetic, memory provenance, allocation failure, bounds, evidence and unsupported-path handling. Do not add testcase-specific summaries or source changes.
5. Check argument recovery on the independent interprocedural fixtures. Compare angr reaching definitions only if Ghidra argument propagation proves impractical; record the engine decision on pilot/fixture evidence rather than final accuracy. Do not expand into a general interprocedural abstract interpreter to force coverage.
6. Publish contracts, limits, reason codes, reuse decisions, deterministic pilot predictions and a report. Preserve every planned pilot cell and distinguish input unavailability, runtime failure and ordinary abstention. Recompute outputs from saved public inputs/IR and verify current method/input identities. Run the regression suite and reverify earlier phases. Phase 7 locks the methods; Phase 8 must freeze final inputs before final prediction is enabled.
